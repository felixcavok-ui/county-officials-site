02

方法与制度

甲

按官职采集，多源拼接

以「县 × 职位 × 时间」面板为骨架：政府工作报告锚定县长序列，人大任免精确化日期， 年鉴与网站快照锚定书记序列，新闻与百科补洞。缺口显式标注，不做插补。

乙

AI 双查 + 人工仲裁

两个模型家族独立抽取同一份简历，字段级比对，分歧进入人工仲裁队列。 每个字段强制保留原文引用片段，程序校验其确为原文子串。

丙

字段级溯源 + 社区报错

已挂接证据的记录附来源 URL 与抓取当日快照索引；证据缺口和冲突由发布闸门及审核台账显式报告。 修订进入版本日志。Spell 级原始数据全部公开，面板由开源脚本生成。

ADJUDICATION LEDGER

审核与裁决

这里不是让你判断“哪个 AI 更可信”，而是逐条回答一个具体事实问题： 某人何时到任、何时离任、是否代理，或某条证据是否应该采用。每张卡先把问题说清楚， 再把本人直接证据、前后任交接锚点和证据异常分开列出；所有可用的原文与采集快照都可直接打开。

三步看懂一张裁决卡

A/B 路是两个独立组装结果；证据卡上的 A/B/C 级才是信源等级，两者不要混淆。

  1. 先看唯一问题
    明确本条到底在裁日期、代理属性，还是证据去留。
  2. 再核逐字引文
    优先本人直接证据；前后任记录只能作为交接锚点。
  3. 最后选动作
    可采某一路、两路皆误、保持未决，或挂账等待补证。

只保存在本机浏览器，导出时写入 JSON；执行落档脚本后会永久记入裁决文书，并展示在已裁决条目上。

点完并导出后，还要做什么？
  1. 先 dry-run 检查：人工裁决运行 py scripts/apply_adjudications.py <JSON>。
  2. 确认后落档：追加 --apply，把结论和裁决人写入 resolutions.csv。
  3. 让事实生效：按脚本列出的各个 runId 重跑 merge；仅导出 JSON 不会修改任期数据。
  4. 刷新页面与面板：重建 demo data 和 panel，抽查后再提交 Git。

「待确认」机器裁决卡使用另一条命令：py scripts/suggest_truncations.py --date YYYY-MM-DD --apply-confirmed <JSON> --apply。

三层数据结构

证据层（evidence，逐字引文+快照索引）是一切结论的依据； 结论层（counties / county_changes / office_spells / persons / career_spells）每行经 evidence_ids 回溯证据； 生成层（县×年面板，由仓库内 scripts/build_panel.py 确定性生成）—— 任何晋升口径的争议都可以回到 spell 级数据重新编码。

POST-ANALYSIS REGISTRATION

研究结果注册

实验经济学有 pre-analysis registration；我们提出 post-analysis registration： 使用本数据库发表（或工作论文阶段）的研究，可自愿提交 replication file。 我们不改动你的代码与模型设定，仅在数据库每次年度更新后重新运行， 检查结论是否随数据时间范围扩展而变化，并以年度报告形式向学术共同体汇报。 这不是打假——有些结果本就是特定时期的产物，知道这一点本身就是知识。

  1. 提交 — replication file（代码 + 环境说明）与论文引用信息
  2. 封存 — 我们登记哈希，不修改、不评判你的设定
  3. 复跑 — 每次数据 release 后自动重跑，记录系数与显著性轨迹
  4. 年报 — 汇总所有注册研究的稳健性，公开发布
